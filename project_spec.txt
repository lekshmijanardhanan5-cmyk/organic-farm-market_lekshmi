Organic farm market System 

1. PROJECT OVERVIEW
-------------------
Project Title:Organic farm market
Tech Stack: MERN (MongoDB, Express, React, Node.js)

2. PROBLEM STATEMENT
--------------------
“Lack of a transparent, direct-to-consumer platform for organic farmers results in reduced farmer income, higher consumer prices, and food wastage.”

3. PROPOSED SOLUTION
--------------------
A digital platform that directly connects verified local organic farmers with consumers, enabling transparent pricing, reduced wastage, and assured product authenticity.

4. USER ROLES & PERMISSIONS
---------------------------
This simplified academic model contains three user roles: Admin, Farmer, and Customer. Roles are mutually exclusive and determine which parts of the system a user can access and which actions they may perform.

- **Admin**
  - Can approve or reject farmer registrations (manage farmer approval state).
  - Can view, create, update, and delete any product.
  - Can view and manage all orders in the system.
  - Can block or delete user accounts.
  - Purpose: overall system administration and trust/quality control.

- **Farmer**
  - Can create and update their own profile.
  - Can create, update, and delete products they own.
  - Can view and manage orders that contain their products (accept, pack, mark as delivered).
  - Cannot manage other farmers' products or orders.
  - Purpose: list and sell produce and manage order fulfillment for their products.

- **Customer**
  - Can browse and view products and product details.
  - Can place orders for available products.
  - Can view their own order history and order statuses.
  - Purpose: purchase products from farmers.

5. DATABASE STRUCTURE (Schemas)
-------------------------------

   The simplified database for the academic model contains three schemas: User, Product, and Order. Each schema focuses only on the fields required for core functionality.

   A. User Schema
Name (String)
Email (String, Unique)
Password (String, Hashed)
Role (String: 'admin' | 'farmer' | 'customer')
CreatedAt (Timestamp)

   B. Product Schema
Title (String)
Description (String)
Price (Number)
Category (String)
ImageURL (String)
FarmerID (Reference to User)
IsAvailable (Boolean, Default: true)
CreatedAt (Timestamp)

   C. Order Schema
UserID (Reference to User – Customer)
Items (Array of Objects: { ItemID (Reference to Product), Quantity (Number) })
TotalAmount (Number)
Status (String: 'Pending' | 'Accepted' | 'Packed' | 'Delivered')
CreatedAt (Timestamp)


6. FEATURE WORKFLOW (The "User Journey")
----------------------------------------
1. Login
User logs in and lands on the Product Page.

2. Browse
User sees a grid/list of Organic Products (fetched from database).
User can click on any product to view detailed product information.

3. Product Details
User views full product details including description, price, and farmer info.

4. Order
User clicks "Order Now" on a selected product and enters quantity.
The system creates a new Order document in MongoDB with status Pending.

5. Farmer/Admin View
Farmer/Admin refreshes dashboard and sees the new order.
Farmer can accept/pack orders containing their products.

6. Order Fulfillment & Notifications
After an order is placed:
- The order appears in the farmer's dashboard (farmers see only orders containing their products).
- The farmer can accept and pack orders that include their products and mark them as delivered when complete.
- Admins can also view and update order statuses across the system.
- Users see order status updates in their order history (Pending → Accepted → Packed → Delivered).

User Notification
Users see the order status updated (Pending → Accepted → Packed → Delivered) within their order history.
7. API ENDPOINTS (The URL Rules)
--------------------------------
Authentication
POST /api/auth/register → Register new user
POST /api/auth/login → Login user
GET /api/auth/profile → Get logged-in user profile
PUT /api/auth/profile → Update user profile

Users
GET /api/users/profile → Get logged-in user profile
PUT /api/users/profile → Update user profile

Customer
GET /api/customer/stats → Get customer statistics (orders, total spent)

Farmer
GET /api/farmer/products → Get farmer's own products
DELETE /api/farmer/products/:id → Delete farmer's own product
GET /api/farmer/stats → Get farmer statistics (products, orders, revenue)

Products
GET /api/products → Get list of organic products
GET /api/products/:id → Get single product by ID (public)
POST /api/products → Create new product (Farmer/Admin)
PUT /api/products/:id → Update product (Farmer/Admin)
DELETE /api/products/:id → Delete product (Admin only)

Orders
POST /api/orders → Place new order
GET /api/orders/user → Get user orders (with optional status filter)
GET /api/orders/farmer → Get farmer orders (only products from logged-in farmer, with optional status filter)
PUT /api/orders/:id/status → Update order status (Farmer/Admin)

Admin
GET /api/admin/roles → Get available user roles
GET /api/admin/users → Get all users (with optional filters: role, isApproved, isBlocked)
PUT /api/admin/users/:id/approve → Approve/reject farmer
PUT /api/admin/users/:id/block → Block/unblock user
DELETE /api/admin/users/:id → Delete user
GET /api/admin/products → Get all products
GET /api/admin/orders → Get all orders
